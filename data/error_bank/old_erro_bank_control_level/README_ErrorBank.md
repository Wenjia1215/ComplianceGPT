# Error Bank (MisRank\>1) — Build Specification & Rationale

> **Status:** current CSV = `error_bank_v1.csv` (this README documents the *current* construction policy and schema).

## Why an Error Bank?

We maintain a focused *challenge set* of query–gold pairs where a plain BM25 retriever **fails to return the gold at Rank 1**. This concentrates evaluation on the hardest retrieval cases so we can measure how Hybrid retrieval and reranking — and especially our QUR-based pipeline — improve over BM25 on **real failure modes**, not just easy questions. This aligns with advisor guidance to report **Error Bank by failure mode** and show per‑mode improvements across systems.

## Source Data

  - Baseline BM25 detailed results per revision:
      - `bm25_rev5_detailed_results.csv`
      - `bm25_rev4_detailed_results.csv`

These are the same BM25 settings used in the main ablations. Building the Error Bank from these files follows the prior “challenge set” README (filter non‑Rank‑1 items), while freezing the baseline and documenting index/query settings.

## Inclusion Rules (this version)

  - **MisRank policy:** include a row **iff `bm25_rank > 1`** (i.e., gold appears at rank 2 or lower).  
      - Rows with “not found in top‑K” (aka *Rank 0/NotFound*) would also be included when present; we treat such cases explicitly as “NotFound”.
  - **Scope:** combine qualifying rows from both Rev.5 (n=100) and Rev.4 (n=36) gold sets.
  - **One failure reason per row:** label each row with exactly **one** `failure_category` chosen from:
      - `Terminology Mismatch` — vocabulary/synonym mismatch (e.g., “least privilege” ↔ AC‑6).  
      - `Generic Phrasing` — underspecified query without concrete terms.  
      - `Semantic Gap` — structurally/semantically appropriate but phrased differently from the gold clause (includes structural/phrasing divergence).  
      These categories match the advisor’s “Generic / Terminology / Structural” guidance.

## Column Schema (current)

This version intentionally **removes older auxiliary columns** and keeps a minimal, audit‑friendly schema:

| Column | Description |
|---|---|
| `id` | Stable row ID (string or int). |
| `query_id` | ID from the gold set. |
| `query` | The original question text. |
| `failure_category` | One of: `Terminology Mismatch`, `Generic Phrasing`, `Semantic Gap`. |
| `framework` | Framework of the gold (e.g., `NIST_SP_800-53`). |
| `gold_source_version` | Precise source version (e.g., `rev5.1.1`, `rev4`). |
| `control_id` | Canonical control / enhancement ID for the gold answer. |
| `bm25_rank` | Position of the gold in BM25’s top‑K (integer ≥2 in this file). |
| `label_rationale` | Short human note justifying the `failure_category`. |
